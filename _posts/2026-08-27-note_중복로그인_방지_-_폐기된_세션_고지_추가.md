### 1. 결론

DB 테이블/컬럼 추가 없이도 **Spring Framework 5.3 + Servlet 표준 API + WAS 간 내부 HTTP 통신**만으로 실무 적용 가능한 중복로그인 종료 메시지 처리가 가능합니다.
중요한 변경점은 기존 방식처럼 신규 로그인 시 이전 `HttpSession.invalidate()`를 즉시 호출하지 않는 것입니다.

```text
[기존 방식]
신규 로그인
 → 기존 HttpSession 찾음
 → invalidate()
 → 기존 사용자 다음 요청
 → 이미 세션이 없어 종료 이유를 알 수 없음
[변경 방식]
신규 로그인
 → 새로운 loginToken 발급
 → loginId의 "현재 유효 token"을 LocalLoginPreventer에 등록
 → 다른 WAS에도 내부 HTTP로 최신 token 통지
 → 기존 HttpSession은 당장은 invalidate하지 않음
 → 기존 사용자 다음 요청
 → Filter가 session의 token과 LocalLoginPreventer 최신 token 비교
 → 불일치 = 중복로그인
 → 이 요청에서 session.invalidate()
 → /login?loginReason=duplicate redirect
 → "다른 위치에서 로그인되어 로그인이 종료되었습니다."
```

`invalidate()` 후 세션 Attribute에 접근하는 것은 불가능하며 `IllegalStateException` 대상입니다. 반대로 `request.getSession(false)`는 세션이 없을 때 새 세션을 만들지 않으므로 Filter에서 안전하게 사용할 수 있습니다. ([자카르타 EE][1])
현재처럼 JBoss 클러스터에서 `<distributable/>`을 사용하는 경우 String 형태의 `loginId`, `loginToken`을 HttpSession Attribute로 두는 것도 적합합니다. Red Hat 문서상 distributable 애플리케이션은 HTTP Session replication 대상이 됩니다. 다만 `<distributable/>` 존재 자체만으로 실제 replication이 정상이라는 보장은 없으므로 별도 실동작 검증은 필요합니다. ([Red Hat Customer Portal][2])

### 5. `LoginState.java` - 신규

단순 UUID만 사용하면 WAS-01과 WAS-02에서 거의 동시에 로그인했을 때 어느 token이 최신인지 서로 다르게 판단할 수 있습니다.
따라서:

```text
version
nodeId
UUID token
```

으로 전체 순서를 결정합니다.

```java
package com.example.common.login;
import java.io.Serializable;
import java.nio.charset.StandardCharsets;
import java.util.Base64;
import java.util.Objects;
/**
 * 특정 loginId의 최신 로그인 상태.
 *
 * [TRACE]
 * SessionService.onLoginSuccess()
 *   -> LoginClusterClient.refreshLatestFromPeers()
 *   -> LocalLoginPreventer.issueNew()
 *   -> LoginState 생성
 *   -> LoginClusterClient.publish()
 *
 * version + nodeId + token 순서로 비교함으로써
 * 노드마다 메시지 수신 순서가 달라도 최종적으로 동일한 상태에 수렴하도록 한다.
 */
public final class LoginState
        implements Serializable, Comparable<LoginState> {
    private static final long serialVersionUID = 1L;
    private final long version;
    private final String nodeId;
    private final String token;
    public LoginState(long version, String nodeId, String token) {
        this.version = version;
        this.nodeId = Objects.requireNonNull(nodeId, "nodeId");
        this.token = Objects.requireNonNull(token, "token");
    }
    public long getVersion() {
        return version;
    }
    public String getNodeId() {
        return nodeId;
    }
    public String getToken() {
        return token;
    }
    /**
     * [TRACE-STATE-01]
     * peer WAS로 전송하기 위한 문자열 생성.
     *
     * JSON library에 의존하지 않도록 단순 Wire Format 사용.
     */
    public String toWire() {
        String encodedNodeId = Base64.getUrlEncoder()
                .withoutPadding()
                .encodeToString(nodeId.getBytes(StandardCharsets.UTF_8));
        return version + "|" + encodedNodeId + "|" + token;
    }
    /**
     * [TRACE-STATE-02]
     * LoginClusterController에서 수신한 문자열을 LoginState로 변환.
     */
    public static LoginState fromWire(String value) {
        if (value == null || value.trim().isEmpty()) {
            throw new IllegalArgumentException("LoginState is empty.");
        }
        String[] values = value.split("\\|", 3);
        if (values.length != 3) {
            throw new IllegalArgumentException(
                    "Invalid LoginState format.");
        }
        long version = Long.parseLong(values[0]);
        String nodeId = new String(
                Base64.getUrlDecoder().decode(values[1]),
                StandardCharsets.UTF_8);
        String token = values[2];
        return new LoginState(version, nodeId, token);
    }
    /**
     * [TRACE-STATE-03]
     * 여러 WAS에서 동시에 로그인되어도 동일한 최신 상태를 결정한다.
     */
    @Override
    public int compareTo(LoginState other) {
        int result = Long.compare(this.version, other.version);
        if (result != 0) {
            return result;
        }
        result = this.nodeId.compareTo(other.nodeId);
        if (result != 0) {
            return result;
        }
        return this.token.compareTo(other.token);
    }
    @Override
    public boolean equals(Object obj) {
        if (this == obj) {
            return true;
        }
        if (!(obj instanceof LoginState)) {
            return false;
        }
        LoginState other = (LoginState) obj;
        return version == other.version
                && nodeId.equals(other.nodeId)
                && token.equals(other.token);
    }
    @Override
    public int hashCode() {
        return Objects.hash(version, nodeId, token);
    }
}
```

### 6. `LoginPreventer.java` - 변경

기존 `HttpSession` 자체를 Map에 저장하고 `invalidateByLoginId()`하는 역할에서 **최신 token 관리 역할**로 변경하는 것이 핵심입니다.

```java
package com.example.common.login;
import java.util.Optional;
/**
 * 로그인 중복 제어 추상화.
 *
 * 구현체:
 * LocalLoginPreventer
 */
public interface LoginPreventer {
    enum ValidationResult {
        CURRENT,
        DUPLICATE,
        UNKNOWN
    }
    /**
     * [TRACE-LP-01]
     * 새로운 로그인이 성공했을 때 최신 LoginState 발급.
     */
    LoginState issueNew(String loginId);
    /**
     * [TRACE-LP-02]
     * 다른 WAS가 전달한 최신 상태 반영.
     *
     * 자신이 가진 정보보다 새로운 경우에만 변경한다.
     */
    void apply(String loginId, LoginState candidate);
    /**
     * [TRACE-LP-03]
     * 해당 사용자의 현재 최신 LoginState 조회.
     */
    Optional<LoginState> findCurrent(String loginId);
    /**
     * [TRACE-LP-04]
     * HttpSession의 loginToken이 현재 최신 token인지 검사.
     */
    ValidationResult validate(String loginId, String sessionToken);
}
```

### 7. `LocalLoginPreventer.java` - 변경

여기서는 더 이상:

```java
ConcurrentHashMap<String, HttpSession>
```

을 사용하지 않습니다.
대신:

```java
ConcurrentHashMap<String, LoginState>
```

개념으로 관리합니다.

```java
package com.example.common.login;
import java.util.Optional;
import java.util.UUID;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ConcurrentMap;
import java.util.concurrent.atomic.AtomicLong;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
/**
 * 현재 WAS JVM 안에서 최신 로그인 상태를 관리한다.
 *
 * 중요:
 * - HttpSession 객체를 저장하지 않는다.
 * - JBoss API를 사용하지 않는다.
 * - loginId -> 최신 LoginState만 저장한다.
 *
 * [TRACE]
 * 신규 로그인:
 * SessionService
 *   -> issueNew()
 *
 * 기존 사용자 요청:
 * DuplicateLoginCheckFilter
 *   -> SessionService
 *      -> validate()
 *
 * peer 통지:
 * LoginClusterController
 *   -> apply()
 */
@Component
public class LocalLoginPreventer implements LoginPreventer {
    private static final Logger log =
            LoggerFactory.getLogger(LocalLoginPreventer.class);
    private final ConcurrentMap<String, Entry> loginStates =
            new ConcurrentHashMap<>();
    /**
     * 현재 노드에서 생성되는 version이 항상 증가하도록 사용.
     */
    private final AtomicLong logicalClock = new AtomicLong();
    private final String nodeId;
    private final long stateTtlMs;
    public LocalLoginPreventer(
            @Value("${login.cluster.node-id:LOCAL}") String nodeId,
            @Value("${login.control.state-ttl-ms:7200000}") long stateTtlMs) {
        this.nodeId = nodeId;
        this.stateTtlMs = stateTtlMs;
    }
    /**
     * [TRACE-LP-01]
     * 새로운 정상 로그인이 성공했을 때 호출된다.
     *
     * 1. 현재 시간 확인
     * 2. 이미 알고 있는 peer version보다 반드시 큰 version 생성
     * 3. UUID token 발급
     * 4. loginId의 최신 상태로 등록
     */
    @Override
    public LoginState issueNew(String loginId) {
        Entry currentEntry = loginStates.get(loginId);
        long knownVersion = currentEntry == null
                ? 0L
                : currentEntry.state.getVersion();
        long version = logicalClock.updateAndGet(previous ->
                Math.max(
                        Math.max(System.currentTimeMillis(), previous + 1),
                        knownVersion + 1));
        LoginState state = new LoginState(
                version,
                nodeId,
                UUID.randomUUID().toString());
        apply(loginId, state);
        log.info(
                "[LOGIN-TRACE][LP-01] New login state issued. "
                + "loginId={}, nodeId={}, version={}, token={}",
                loginId,
                nodeId,
                state.getVersion(),
                state.getToken());
        return state;
    }
    /**
     * [TRACE-LP-02]
     * peer WAS 또는 자신의 신규 상태를 반영한다.
     *
     * candidate가 현재 값보다 최신인 경우에만 교체하므로
     * HTTP 메시지가 순서가 바뀌어 도착해도 과거 값으로 rollback되지 않는다.
     */
    @Override
    public void apply(String loginId, LoginState candidate) {
        logicalClock.updateAndGet(previous ->
                Math.max(previous, candidate.getVersion()));
        loginStates.compute(loginId, (key, current) -> {
            long now = System.currentTimeMillis();
            if (current == null
                    || candidate.compareTo(current.state) > 0) {
                log.info(
                        "[LOGIN-TRACE][LP-02] Login state updated. "
                        + "loginId={}, version={}, nodeId={}",
                        loginId,
                        candidate.getVersion(),
                        candidate.getNodeId());
                return new Entry(candidate, now);
            }
            current.touch(now);
            return current;
        });
    }
    /**
     * [TRACE-LP-03]
     * 현재 WAS가 알고 있는 최신 로그인 상태 조회.
     */
    @Override
    public Optional<LoginState> findCurrent(String loginId) {
        Entry entry = loginStates.get(loginId);
        if (entry == null) {
            return Optional.empty();
        }
        entry.touch(System.currentTimeMillis());
        return Optional.of(entry.state);
    }
    /**
     * [TRACE-LP-04]
     * 사용자의 HttpSession에 저장된 token과
     * 서버가 알고 있는 최신 token을 비교한다.
     *
     * 동일     -> CURRENT
     * 다름     -> DUPLICATE
     * 정보없음 -> UNKNOWN
     */
    @Override
    public ValidationResult validate(
            String loginId,
            String sessionToken) {
        Entry entry = loginStates.get(loginId);
        if (entry == null) {
            return ValidationResult.UNKNOWN;
        }
        entry.touch(System.currentTimeMillis());
        if (entry.state.getToken().equals(sessionToken)) {
            return ValidationResult.CURRENT;
        }
        return ValidationResult.DUPLICATE;
    }
    /**
     * [TRACE-LP-05]
     * 장기간 사용되지 않은 로그인 상태 제거.
     *
     * 주의:
     * stateTtlMs는 반드시 HttpSession timeout보다 길어야 한다.
     *
     * 예:
     * HttpSession timeout = 30분
     * state TTL = 120분
     */
    @Scheduled(
        fixedDelayString =
            "${login.control.cleanup-interval-ms:600000}"
    )
    public void cleanupExpiredStates() {
        long cutoff =
                System.currentTimeMillis() - stateTtlMs;
        loginStates.entrySet().removeIf(entry ->
                entry.getValue().lastTouchedAt < cutoff);
    }
    /**
     * LoginState 자체는 immutable하게 유지하고
     * 마지막 접근시간만 JVM 내부 관리한다.
     */
    private static final class Entry {
        private final LoginState state;
        private volatile long lastTouchedAt;
        private Entry(LoginState state, long lastTouchedAt) {
            this.state = state;
            this.lastTouchedAt = lastTouchedAt;
        }
        private void touch(long now) {
            this.lastTouchedAt = now;
        }
    }
}
```

### 8. 중요한 설계

정상 로그아웃 시에도:

```java
loginStates.remove(loginId);
```

를 호출하면 안 됩니다.
예를 들어:

```text
LOGIN-A token=A
↓
LOGIN-B token=B 발생
↓
A는 중복로그인 상태
↓
B가 정상 로그아웃
↓
최신 token B 삭제
↓
A가 다시 요청
↓
A가 다시 정상 사용자처럼 살아날 가능성
```

이 생기기 때문입니다.
따라서 최신 token은 세션 timeout보다 충분히 긴 TTL 동안 유지합니다.

### 9. `LoginControlConfig.java` - 신규

별도 Apache HttpClient/JBoss 라이브러리도 필요 없습니다.

```java
package com.example.common.login;
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;
import org.springframework.scheduling.annotation.EnableScheduling;
import org.springframework.web.client.RestTemplate;
import org.springframework.http.client.SimpleClientHttpRequestFactory;
/**
 * 로그인 클러스터 제어 Spring 설정.
 *
 * [TRACE]
 * LoginClusterClient
 *   -> loginClusterRestTemplate
 *      -> peer WAS 내부 Controller 호출
 */
@Configuration
@EnableScheduling
public class LoginControlConfig {
    /**
     * [TRACE-CONFIG-01]
     * WAS간 내부 HTTP 통신 전용 RestTemplate.
     *
     * 일반 사용자 요청용 RestTemplate과 분리하여
     * 검색/외부 API Connection Pool과 영향을 주고받지 않게 한다.
     */
    @Bean(name = "loginClusterRestTemplate")
    public RestTemplate loginClusterRestTemplate() {
        SimpleClientHttpRequestFactory factory =
                new SimpleClientHttpRequestFactory();
        factory.setConnectTimeout(500);
        factory.setReadTimeout(1000);
        return new RestTemplate(factory);
    }
}
```

## 10. 로그인 시에만 사용하는 통신이므로 별도 Connection Pool까지 도입할 필요성은 낮습니다.

### 10-1. `LoginClusterClient.java` - 신규

이 클래스가 JBoss `CommandDispatcher` 역할을 Spring HTTP로 대체합니다.

```java
package com.example.common.login;
import java.util.ArrayList;
import java.util.Arrays;
import java.util.List;
import java.util.Map;
import java.util.Optional;
import java.util.concurrent.ConcurrentHashMap;
import java.util.stream.Collectors;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.HttpEntity;
import org.springframework.http.HttpHeaders;
import org.springframework.http.MediaType;
import org.springframework.http.ResponseEntity;
import org.springframework.scheduling.annotation.Scheduled;
import org.springframework.stereotype.Component;
import org.springframework.util.LinkedMultiValueMap;
import org.springframework.util.MultiValueMap;
import org.springframework.web.client.RestTemplate;
/**
 * WAS간 최신 로그인 상태를 전달한다.
 *
 * JBoss clustering API를 전혀 사용하지 않는다.
 *
 * [TRACE]
 * 신규 로그인:
 * SessionService.onLoginSuccess()
 *   -> refreshLatestFromPeers()
 *   -> LocalLoginPreventer.issueNew()
 *   -> publish()
 *
 * 수신:
 * peer LoginClusterController
 *   -> LocalLoginPreventer.apply()
 */
@Component
public class LoginClusterClient {
    private static final Logger log =
            LoggerFactory.getLogger(LoginClusterClient.class);
    private final RestTemplate restTemplate;
    private final LoginPreventer loginPreventer;
    private final boolean enabled;
    private final String secret;
    private final List<String> peerUrls;
    /**
     * peer 전송 실패 시 DB가 없으므로 메모리에서 재시도한다.
     *
     * loginId별 최신 상태 하나만 유지한다.
     */
    private final Map<String, LoginState> pending =
            new ConcurrentHashMap<>();
    public LoginClusterClient(
            @Qualifier("loginClusterRestTemplate")
            RestTemplate restTemplate,
            LoginPreventer loginPreventer,
            @Value("${login.cluster.enabled:false}")
            boolean enabled,
            @Value("${login.cluster.secret:}")
            String secret,
            @Value("${login.cluster.peer-urls:}")
            String peerUrls) {
        this.restTemplate = restTemplate;
        this.loginPreventer = loginPreventer;
        this.enabled = enabled;
        this.secret = secret == null ? "" : secret.trim();
        this.peerUrls = parsePeerUrls(peerUrls);
        if (enabled && this.secret.isEmpty()) {
            throw new IllegalStateException(
                    "login.cluster.secret must be configured.");
        }
    }
    /**
     * [TRACE-CLUSTER-01]
     * 신규 token을 만들기 전에 peer WAS가 더 최신 상태를
     * 가지고 있는지 조회한다.
     *
     * 이 과정을 먼저 수행해야 현재 노드의 신규 login version이
     * 기존 cluster version보다 커질 수 있다.
     */
    public Optional<LoginState> refreshLatestFromPeers(
            String loginId) {
        if (!enabled) {
            return Optional.empty();
        }
        LoginState latest = null;
        for (String peerUrl : peerUrls) {
            try {
                Optional<LoginState> remote =
                        requestCurrent(peerUrl, loginId);
                if (remote.isPresent()
                        && (latest == null
                        || remote.get().compareTo(latest) > 0)) {
                    latest = remote.get();
                }
            } catch (RuntimeException e) {
                log.warn(
                        "[LOGIN-TRACE][CLUSTER-01] "
                        + "Failed to read peer login state. "
                        + "peer={}, loginId={}",
                        peerUrl,
                        loginId,
                        e);
            }
        }
        if (latest != null) {
            loginPreventer.apply(loginId, latest);
        }
        return Optional.ofNullable(latest);
    }
    /**
     * [TRACE-CLUSTER-02]
     * 새로운 최신 로그인 상태를 모든 peer WAS에 전달한다.
     */
    public void publish(
            String loginId,
            LoginState state) {
        if (!enabled) {
            return;
        }
        boolean success = sendToAll(loginId, state);
        if (!success) {
            /*
             * 더 오래된 실패 상태가 존재하더라도 최신 값으로 교체.
             */
            pending.compute(loginId, (key, old) -> {
                if (old == null || state.compareTo(old) > 0) {
                    return state;
                }
                return old;
            });
        }
    }
    /**
     * [TRACE-CLUSTER-03]
     * peer 장애/일시 네트워크 오류로 전송하지 못했던 상태 재전송.
     *
     * DB를 사용하지 않으므로 JVM 재기동 시 pending은 소실된다.
     */
    @Scheduled(
        fixedDelayString =
            "${login.cluster.retry-interval-ms:5000}"
    )
    public void retryPending() {
        if (!enabled || pending.isEmpty()) {
            return;
        }
        pending.forEach((loginId, state) -> {
            if (sendToAll(loginId, state)) {
                pending.remove(loginId, state);
                log.info(
                        "[LOGIN-TRACE][CLUSTER-03] "
                        + "Pending state synchronized. loginId={}",
                        loginId);
            }
        });
    }
    /**
     * [TRACE-CLUSTER-04]
     * 전체 peer에 상태 전달.
     */
    private boolean sendToAll(
            String loginId,
            LoginState state) {
        boolean allSuccess = true;
        for (String peerUrl : peerUrls) {
            try {
                sendState(peerUrl, loginId, state);
            } catch (RuntimeException e) {
                allSuccess = false;
                log.error(
                        "[LOGIN-TRACE][CLUSTER-04] "
                        + "Failed to publish login state. "
                        + "peer={}, loginId={}",
                        peerUrl,
                        loginId,
                        e);
            }
        }
        return allSuccess;
    }
    /**
     * [TRACE-CLUSTER-05]
     * peer /state Endpoint 호출.
     */
    private void sendState(
            String peerUrl,
            String loginId,
            LoginState state) {
        MultiValueMap<String, String> form =
                new LinkedMultiValueMap<>();
        form.add("loginId", loginId);
        form.add("state", state.toWire());
        HttpHeaders headers = createHeaders();
        HttpEntity<MultiValueMap<String, String>> request =
                new HttpEntity<>(form, headers);
        restTemplate.postForEntity(
                peerUrl + "/internal/login-control/state",
                request,
                String.class);
    }
    /**
     * [TRACE-CLUSTER-06]
     * 해당 loginId의 최신 상태를 peer에서 조회.
     */
    private Optional<LoginState> requestCurrent(
            String peerUrl,
            String loginId) {
        MultiValueMap<String, String> form =
                new LinkedMultiValueMap<>();
        form.add("loginId", loginId);
        HttpEntity<MultiValueMap<String, String>> request =
                new HttpEntity<>(form, createHeaders());
        ResponseEntity<String> response =
                restTemplate.postForEntity(
                        peerUrl
                            + "/internal/login-control/current",
                        request,
                        String.class);
        String body = response.getBody();
        if (body == null || body.trim().isEmpty()) {
            return Optional.empty();
        }
        return Optional.of(LoginState.fromWire(body.trim()));
    }
    private HttpHeaders createHeaders() {
        HttpHeaders headers = new HttpHeaders();
        headers.setContentType(
                MediaType.APPLICATION_FORM_URLENCODED);
        headers.set(
                LoginControlConstants.HEADER_CLUSTER_KEY,
                secret);
        return headers;
    }
    private List<String> parsePeerUrls(String value) {
        if (value == null || value.trim().isEmpty()) {
            return new ArrayList<>();
        }
        return Arrays.stream(value.split(","))
                .map(String::trim)
                .filter(v -> !v.isEmpty())
                .map(v -> v.endsWith("/")
                        ? v.substring(0, v.length() - 1)
                        : v)
                .collect(Collectors.toList());
    }
}
```

### 10-2. `LoginClusterController.java` - 신규

이 URL은 외부 사용자가 호출하는 API가 아니라 **WAS-01 ↔ WAS-02 전용 내부 Endpoint**입니다.

```java
package com.example.common.login;
import java.nio.charset.StandardCharsets;
import java.security.MessageDigest;
import java.util.Optional;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.PostMapping;
import org.springframework.web.bind.annotation.RequestHeader;
import org.springframework.web.bind.annotation.RequestMapping;
import org.springframework.web.bind.annotation.RequestParam;
import org.springframework.web.bind.annotation.RestController;
/**
 * 다른 WAS에서 전달되는 LoginState 처리.
 *
 * 중요:
 * 이 Controller는 상태를 다시 peer로 전송하지 않는다.
 * 따라서:
 *
 * WAS-01 -> WAS-02
 *             |
 *             X 다시 WAS-01로 broadcast하지 않음
 *
 * 무한 전파를 방지한다.
 */
@RestController
@RequestMapping("/internal/login-control")
public class LoginClusterController {
    private static final Logger log =
            LoggerFactory.getLogger(LoginClusterController.class);
    private final LoginPreventer loginPreventer;
    private final String secret;
    public LoginClusterController(
            LoginPreventer loginPreventer,
            @Value("${login.cluster.secret:}")
            String secret) {
        this.loginPreventer = loginPreventer;
        this.secret = secret == null ? "" : secret.trim();
    }
    /**
     * [TRACE-REMOTE-01]
     * peer WAS에서 발생한 신규 LoginState 수신.
     */
    @PostMapping(
        value = "/state",
        produces = "text/plain;charset=UTF-8"
    )
    public ResponseEntity<String> updateState(
            @RequestHeader(
                value = LoginControlConstants.HEADER_CLUSTER_KEY,
                required = false)
            String clusterKey,
            @RequestParam("loginId")
            String loginId,
            @RequestParam("state")
            String stateValue) {
        if (!isAuthorized(clusterKey)) {
            return ResponseEntity.status(403).body("FORBIDDEN");
        }
        if (!isValidLoginId(loginId)) {
            return ResponseEntity.badRequest()
                    .body("INVALID_LOGIN_ID");
        }
        try {
            LoginState state =
                    LoginState.fromWire(stateValue);
            loginPreventer.apply(loginId, state);
            log.info(
                    "[LOGIN-TRACE][REMOTE-01] "
                    + "Remote state received. "
                    + "loginId={}, nodeId={}, version={}",
                    loginId,
                    state.getNodeId(),
                    state.getVersion());
            return ResponseEntity.ok("OK");
        } catch (RuntimeException e) {
            log.warn(
                    "[LOGIN-TRACE][REMOTE-01] "
                    + "Invalid remote login state.",
                    e);
            return ResponseEntity.badRequest()
                    .body("INVALID_STATE");
        }
    }
    /**
     * [TRACE-REMOTE-02]
     * peer WAS가 신규 로그인 전에
     * 현재 최신 LoginState를 조회할 때 호출.
     */
    @PostMapping(
        value = "/current",
        produces = "text/plain;charset=UTF-8"
    )
    public ResponseEntity<String> current(
            @RequestHeader(
                value = LoginControlConstants.HEADER_CLUSTER_KEY,
                required = false)
            String clusterKey,
            @RequestParam("loginId")
            String loginId) {
        if (!isAuthorized(clusterKey)) {
            return ResponseEntity.status(403).body("FORBIDDEN");
        }
        if (!isValidLoginId(loginId)) {
            return ResponseEntity.badRequest()
                    .body("INVALID_LOGIN_ID");
        }
        Optional<LoginState> state =
                loginPreventer.findCurrent(loginId);
        if (!state.isPresent()) {
            return ResponseEntity.noContent().build();
        }
        return ResponseEntity.ok(state.get().toWire());
    }
    /**
     * [TRACE-REMOTE-03]
     * 내부 요청 공유 secret 비교.
     *
     * 단순 String.equals보다 MessageDigest.isEqual()을 사용한다.
     */
    private boolean isAuthorized(String received) {
        if (secret.isEmpty()
                || received == null
                || received.isEmpty()) {
            return false;
        }
        byte[] expectedBytes =
                secret.getBytes(StandardCharsets.UTF_8);
        byte[] receivedBytes =
                received.getBytes(StandardCharsets.UTF_8);
        return MessageDigest.isEqual(
                expectedBytes,
                receivedBytes);
    }
    private boolean isValidLoginId(String loginId) {
        return loginId != null
                && !loginId.trim().isEmpty()
                && loginId.length() <= 200;
    }
}
```

### 11-1. `SessionService.java` - 변경

실질적인 중복로그인 핵심 서비스입니다.

```java
package com.example.common.login;
import javax.servlet.http.HttpSession;
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;
import org.springframework.stereotype.Service;
/**
 * 로그인 HttpSession과 LoginPreventer를 연결한다.
 *
 * [TRACE]
 * Login 성공:
 * LoginSessionManager.loginSuccess()
 *   -> onLoginSuccess()
 *
 * 모든 화면 요청:
 * DuplicateLoginCheckFilter
 *   -> LoginSessionManager.check()
 *      -> validateSession()
 */
@Service
public class SessionService {
    private static final Logger log =
            LoggerFactory.getLogger(SessionService.class);
    public enum SessionCheckResult {
        ANONYMOUS,
        CURRENT,
        DUPLICATE,
        UNKNOWN,
        LEGACY,
        INVALID
    }
    private final LoginPreventer loginPreventer;
    private final LoginClusterClient clusterClient;
    public SessionService(
            LoginPreventer loginPreventer,
            LoginClusterClient clusterClient) {
        this.loginPreventer = loginPreventer;
        this.clusterClient = clusterClient;
    }
    /**
     * [TRACE-SESSION-01]
     * 로그인 인증이 최종 성공한 직후 딱 한 번 호출한다.
     *
     * 처리 순서가 중요하다.
     *
     * 1. peer 최신 상태 조회
     * 2. 신규 LoginState 생성
     * 3. 현재 HttpSession에 loginId/token 저장
     * 4. peer WAS에 신규 상태 통지
     *
     * 기존 HttpSession.invalidate()는 여기서 절대 하지 않는다.
     */
    public void onLoginSuccess(
            String loginId,
            HttpSession session) {
        if (loginId == null
                || loginId.trim().isEmpty()) {
            throw new IllegalArgumentException(
                    "loginId must not be empty.");
        }
        if (session == null) {
            throw new IllegalArgumentException(
                    "session must not be null.");
        }
        String normalizedLoginId = loginId.trim();
        // [TRACE-SESSION-01-1]
        // peer가 가진 최신 version을 Local에 먼저 반영
        clusterClient.refreshLatestFromPeers(
                normalizedLoginId);
        // [TRACE-SESSION-01-2]
        // peer보다 큰 신규 version/token 생성
        LoginState state =
                loginPreventer.issueNew(
                        normalizedLoginId);
        // [TRACE-SESSION-01-3]
        // String만 저장하므로 distributable session에 적합
        session.setAttribute(
                LoginControlConstants.SESSION_LOGIN_ID,
                normalizedLoginId);
        session.setAttribute(
                LoginControlConstants.SESSION_LOGIN_TOKEN,
                state.getToken());
        // [TRACE-SESSION-01-4]
        // 다른 WAS에 최신 token 전달
        clusterClient.publish(
                normalizedLoginId,
                state);
        log.info(
                "[LOGIN-TRACE][SESSION-01] Login completed. "
                + "loginId={}, sessionId={}, token={}",
                normalizedLoginId,
                safeSessionId(session),
                state.getToken());
    }
    /**
     * [TRACE-SESSION-02]
     * 기존 사용자의 모든 요청에서 호출.
     *
     * 현재 HttpSession token이 최신 token과 동일한지 확인한다.
     */
    public SessionCheckResult validateSession(
            HttpSession session) {
        if (session == null) {
            return SessionCheckResult.ANONYMOUS;
        }
        try {
            Object loginIdObject =
                    session.getAttribute(
                        LoginControlConstants.SESSION_LOGIN_ID);
            if (loginIdObject == null) {
                // 로그인 전 Session.
                return SessionCheckResult.ANONYMOUS;
            }
            String loginId =
                    String.valueOf(loginIdObject);
            Object tokenObject =
                    session.getAttribute(
                        LoginControlConstants.SESSION_LOGIN_TOKEN);
            if (tokenObject == null) {
                /*
                 * 기능 적용 전에 생성되어 살아있던 기존 Session.
                 */
                return SessionCheckResult.LEGACY;
            }
            String sessionToken =
                    String.valueOf(tokenObject);
            LoginPreventer.ValidationResult validation =
                    loginPreventer.validate(
                            loginId,
                            sessionToken);
            /*
             * 이 WAS가 재기동되었거나 사용자가 다른 WAS로
             * Failover되어 Local Map에 정보가 없는 경우.
             */
            if (validation
                    == LoginPreventer.ValidationResult.UNKNOWN) {
                // [TRACE-SESSION-02-1]
                // peer WAS에서 한 번만 최신 상태 복원
                clusterClient.refreshLatestFromPeers(loginId);
                validation =
                        loginPreventer.validate(
                                loginId,
                                sessionToken);
            }
            if (validation
                    == LoginPreventer.ValidationResult.CURRENT) {
                return SessionCheckResult.CURRENT;
            }
            if (validation
                    == LoginPreventer.ValidationResult.DUPLICATE) {
                log.warn(
                        "[LOGIN-TRACE][SESSION-02] "
                        + "Duplicate login detected. "
                        + "loginId={}, sessionId={}, sessionToken={}",
                        loginId,
                        safeSessionId(session),
                        sessionToken);
                return SessionCheckResult.DUPLICATE;
            }
            /*
             * peer에도 정보가 없다면 보안상 현재 Session을
             * 정상이라고 임의 판단하지 않는다.
             */
            return SessionCheckResult.UNKNOWN;
        } catch (IllegalStateException e) {
            // 다른 Thread 등에서 이미 invalidate된 경우
            return SessionCheckResult.INVALID;
        }
    }
    /**
     * [TRACE-SESSION-03]
     * Filter에서 DUPLICATE를 확인한 후 물리적으로 Session 종료.
     */
    public void invalidate(HttpSession session) {
        if (session == null) {
            return;
        }
        try {
            String sessionId = session.getId();
            session.invalidate();
            log.info(
                    "[LOGIN-TRACE][SESSION-03] "
                    + "Session invalidated. sessionId={}",
                    sessionId);
        } catch (IllegalStateException e) {
            log.debug(
                    "[LOGIN-TRACE][SESSION-03] "
                    + "Session already invalidated.");
        }
    }
    /**
     * [TRACE-SESSION-04]
     * 정상 Logout에서도 latest token을 LocalLoginPreventer에서
     * 삭제하지 않는 것이 중요하다.
     */
    public void logout(HttpSession session) {
        invalidate(session);
    }
    private String safeSessionId(HttpSession session) {
        try {
            return session.getId();
        } catch (IllegalStateException e) {
            return "INVALIDATED";
        }
    }
}
```

### 11-5. `DuplicateLoginCheckFilter.java` - 신규

가장 중요한 클래스입니다.
기존 Controller/Interceptor가 `request.getSession()`을 호출하기 **전**에 실행해야 합니다.

```java
package com.example.common.login;
import java.io.IOException;
import javax.servlet.FilterChain;
import javax.servlet.ServletException;
import javax.servlet.http.HttpServletRequest;
import javax.servlet.http.HttpServletResponse;
import javax.servlet.http.HttpSession;
import org.springframework.beans.factory.annotation.Value;
import org.springframework.stereotype.Component;
import org.springframework.web.filter.OncePerRequestFilter;
/**
 * 모든 사용자 요청의 가장 앞에서 로그인 token 유효성을 검사.
 *
 * [TRACE]
 * Browser
 *   -> DuplicateLoginCheckFilter
 *      -> request.getSession(false)
 *      -> LoginSessionManager.check()
 *      -> SessionService.validateSession()
 *      -> LocalLoginPreventer.validate()
 *
 * DUPLICATE:
 *   -> session.invalidate()
 *   -> 로그인 화면 redirect
 */
@Component("duplicateLoginCheckFilter")
public class DuplicateLoginCheckFilter
        extends OncePerRequestFilter {
    private final LoginSessionManager loginSessionManager;
    private final String loginUrl;
    private final boolean allowLegacySession;
    public DuplicateLoginCheckFilter(
            LoginSessionManager loginSessionManager,
            @Value("${login.control.login-url:/login.do}")
            String loginUrl,
            @Value("${login.control.allow-legacy-session:true}")
            boolean allowLegacySession) {
        this.loginSessionManager =
                loginSessionManager;
        this.loginUrl = loginUrl;
        this.allowLegacySession =
                allowLegacySession;
    }
    /**
     * [TRACE-FILTER-01]
     * 실제 사용자 요청 검증.
     *
     * getSession(false)를 사용하므로 세션이 없는 사용자의 요청에
     * 새로운 Session을 생성하지 않는다.
     */
    @Override
    protected void doFilterInternal(
            HttpServletRequest request,
            HttpServletResponse response,
            FilterChain filterChain)
            throws ServletException, IOException {
        // [TRACE-FILTER-01-1]
        // 절대 request.getSession() 사용하지 않음.
        HttpSession session =
                request.getSession(false);
        if (session == null) {
            filterChain.doFilter(request, response);
            return;
        }
        // [TRACE-FILTER-01-2]
        SessionService.SessionCheckResult result =
                loginSessionManager.check(session);
        switch (result) {
        case ANONYMOUS:
        case CURRENT:
            filterChain.doFilter(request, response);
            return;
        case LEGACY:
            /*
             * 신규 기능 최초 배포 직후 기존 로그인 사용자를
             * 모두 강제 로그아웃시키지 않기 위한 Migration 옵션.
             */
            if (allowLegacySession) {
                filterChain.doFilter(request, response);
                return;
            }
            terminate(
                    request,
                    response,
                    session,
                    LoginControlConstants.REASON_SESSION_EXPIRED);
            return;
        case DUPLICATE:
            // [TRACE-FILTER-01-3]
            // 여기서 처음 실제 invalidate() 수행.
            terminate(
                    request,
                    response,
                    session,
                    LoginControlConstants.REASON_DUPLICATE);
            return;
        case UNKNOWN:
        case INVALID:
        default:
            /*
             * 정상 여부를 확인할 수 없는 Session을 임의 허용하지 않음.
             */
            terminate(
                    request,
                    response,
                    session,
                    LoginControlConstants.REASON_SESSION_EXPIRED);
        }
    }
    /**
     * [TRACE-FILTER-02]
     * 중복로그인으로 판정된 Session을 실제 폐기하고
     * 사용자에게 종료 사유를 전달한다.
     */
    private void terminate(
            HttpServletRequest request,
            HttpServletResponse response,
            HttpSession session,
            String reason)
            throws IOException {
        loginSessionManager.invalidate(session);
        response.setHeader(
                "Cache-Control",
                "no-store, no-cache, must-revalidate");
        if (isAjaxRequest(request)) {
            /*
             * AJAX에서 302 redirect하면 Login HTML이 AJAX 응답으로
             * 들어갈 수 있으므로 401을 명확히 반환.
             */
            response.setStatus(
                    HttpServletResponse.SC_UNAUTHORIZED);
            response.setContentType(
                    "application/json;charset=UTF-8");
            if (LoginControlConstants.REASON_DUPLICATE
                    .equals(reason)) {
                response.getWriter().write(
                    "{\"code\":\"DUPLICATE_LOGIN\","
                    + "\"message\":"
                    + "\"다른 위치에서 로그인되어 "
                    + "현재 로그인이 종료되었습니다. "
                    + "다시 로그인해 주세요.\"}");
            } else {
                response.getWriter().write(
                    "{\"code\":\"SESSION_EXPIRED\","
                    + "\"message\":"
                    + "\"로그인 세션이 종료되었습니다. "
                    + "다시 로그인해 주세요.\"}");
            }
            return;
        }
        /*
         * 일반 페이지 요청.
         */
        String redirectUrl =
                request.getContextPath()
                + loginUrl
                + "?loginReason="
                + reason;
        response.sendRedirect(redirectUrl);
    }
    /**
     * [TRACE-FILTER-03]
     * 일반 navigation과 AJAX/REST 요청 구분.
     */
    private boolean isAjaxRequest(
            HttpServletRequest request) {
        String requestedWith =
                request.getHeader("X-Requested-With");
        if ("XMLHttpRequest".equalsIgnoreCase(
                requestedWith)) {
            return true;
        }
        String accept =
                request.getHeader("Accept");
        return accept != null
                && accept.contains("application/json");
    }
    /**
     * [TRACE-FILTER-04]
     * WAS간 내부 로그인 동기화 API는 사용자 Session 검사 대상에서 제외.
     */
    @Override
    protected boolean shouldNotFilter(
            HttpServletRequest request) {
        String uri = request.getRequestURI();
        String contextPath =
                request.getContextPath();
        String internalPath =
                contextPath
                + "/internal/login-control/";
        return uri.startsWith(internalPath);
    }
}
```

## 12. `request.getSession(false)`는 유효한 Session이 없으면 `null`만 반환하고 새 Session을 생성하지 않는 것이 Servlet 표준 동작입니다. ([자카르타 EE][1])

### 12-1. `web.xml` - 변경

Spring Boot가 아닌 Spring 5.3 전통 WAR 구조라면 `@Component`만으로 Filter Chain에 들어간다고 가정하면 안 됩니다.
`DelegatingFilterProxy`를 등록합니다.
**반드시 `request.getSession()`을 호출하는 기존 Filter보다 앞에 배치합니다.**

```xml
<!-- =========================================================
     [TRACE-WEB-01]
     중복 로그인 확인 Filter
     반드시 Session을 생성하는 기존 Filter보다 먼저 정의
     ========================================================= -->
<filter>
    <filter-name>duplicateLoginCheckFilter</filter-name>
    <filter-class>
        org.springframework.web.filter.DelegatingFilterProxy
    </filter-class>
    <async-supported>true</async-supported>
</filter>
<filter-mapping>
    <filter-name>duplicateLoginCheckFilter</filter-name>
    <url-pattern>/*</url-pattern>
    <dispatcher>REQUEST</dispatcher>
</filter-mapping>
```

Filter 이름:

```text
duplicateLoginCheckFilter
```

과 Bean 이름:

```java
@Component("duplicateLoginCheckFilter")
```

이 정확히 같아야 합니다.

### 12-2. Filter 실행 순서

```text
1. duplicateLoginCheckFilter       ← 가장 먼저
2. 기존 Encoding/Site Filter
3. DispatcherServlet
4. HandlerInterceptor
5. Controller
```

### 14-2. 기존 `HttpSessionBindingListener`가 있다면 반드시 변경

이전에 사용하던 형태가 다음과 같다면:

```java
@Override
public void valueBound(HttpSessionBindingEvent event) {
    if (EgovMultiLoginPreventor.findByLoginId(event.getName())) {
        EgovMultiLoginPreventor.invalidateByLoginId(
                event.getName());
    }
    EgovMultiLoginPreventor.loginUsers.put(
            event.getName(),
            event.getSession());
}
```

이 로직은 **새 구조에서는 사용하면 안 됩니다.**
특히 다음 코드:

```java
invalidateByLoginId(...)
```

를 반드시 제거해야 합니다.
이유:

```text
valueBound
 → 이전 Session 즉시 invalidate
 → DuplicateLoginCheckFilter 실행 전 Session 소실
 → 중복로그인 종료 이유 표시 불가능
```

Listener가 다른 목적으로 필요하지 않다면 아예 제거할 수 있습니다.
Listener를 계속 유지해야 한다면:

```java
public class EgovHttpSessionBindingListener
        implements HttpSessionBindingListener {
    private static final Logger log =
            LoggerFactory.getLogger(
                EgovHttpSessionBindingListener.class);
    /**
     * [TRACE-LISTENER-01]
     * Session Attribute bind 로깅 용도.
     *
     * 중복로그인 처리/Session invalidate는 하지 않는다.
     */
    @Override
    public void valueBound(
            HttpSessionBindingEvent event) {
        log.debug(
                "[LOGIN-TRACE][LISTENER-01] "
                + "valueBound name={}, sessionId={}",
                event.getName(),
                event.getSession().getId());
    }
    /**
     * [TRACE-LISTENER-02]
     * Session Attribute unbind 로깅 용도.
     *
     * LocalLoginPreventer 최신 token을 삭제하지 않는다.
     */
    @Override
    public void valueUnbound(
            HttpSessionBindingEvent event) {
        log.debug(
                "[LOGIN-TRACE][LISTENER-02] "
                + "valueUnbound name={}",
                event.getName());
    }
}
```

### 14-3. 최초 배포 시 `allow-legacy-session`

이 부분은 운영 배포에서 중요합니다.
새 기능 배포 전에 로그인한 Session에는:

```text
__LOGIN_CONTROL_LOGIN_ID
__LOGIN_CONTROL_LOGIN_TOKEN
```

이 존재하지 않습니다.
따라서 최초 배포:

```properties
login.control.allow-legacy-session=true
```

로 운영합니다.
예를 들어 현재 `session-timeout=30분`이라면 기존 Session이 모두 자연 종료될 시간을 충분히 지난 후:

```properties
login.control.allow-legacy-session=false
```

로 변경하는 것이 안전합니다.
그 이후 `loginId`는 있는데 `loginToken`이 없는 비정상 Session은 정상 로그인으로 인정하지 않습니다.

### 14-5. 기존 사용자의 중복로그인 검출 TRACE

기존 사용자:

```text
Session-A
LOGIN_ID=user01
LOGIN_TOKEN=A
```

신규 로그인:

```text
Session-B
LOGIN_ID=user01
LOGIN_TOKEN=B
```

기존 사용자가 상품상세 클릭:

```text
Browser
 │
 ▼
[TRACE-FILTER-01]
DuplicateLoginCheckFilter
 │
 ├─ request.getSession(false)
 │
 └─ Session-A 취득
       │
       ▼
[TRACE-MANAGER-02]
LoginSessionManager.check()
       │
       ▼
[TRACE-SESSION-02]
SessionService.validateSession()
       │
       ▼
[TRACE-LP-04]
LocalLoginPreventer.validate()
       │
       ├─ Session Token = A
       │
       └─ Current Token = B
                │
                ▼
             DUPLICATE
                │
                ▼
[TRACE-FILTER-02]
session.invalidate()
                │
                ▼
/login.do?loginReason=duplicate
                │
                ▼
"다른 위치에서 로그인되어 현재 로그인이 종료되었습니다."
```

이 시점에는 Controller까지 요청이 도달하지 않습니다.
즉:

```text
Filter
 ├─ 정상 → Controller 진행
 └─ 중복 → invalidate + redirect
```

## 15. 가 됩니다.

### 15-1. WAS가 달라도 동작하는 과정

예:

```text
기존 사용자
 → WAS-01
 → token=A
신규 사용자
 → WAS-02
```

신규 로그인:

```text
WAS-02
SessionService
 ↓
WAS-01 current 상태 조회
 ↓
A 확인
 ↓
새 token B 생성
 ↓
WAS-02 LocalLoginPreventer = B
 ↓
HTTP
 ↓
WAS-01 LocalLoginPreventer = B
```

이후 기존 사용자가 WAS-01으로 들어오면:

```text
Session token=A
Local current=B
→ 중복로그인
```

L4 Round-Robin으로 WAS-02에 들어와도, HTTP Session replication이 정상이라 Session을 WAS-02가 받아 처리할 수 있다면:

```text
Session token=A
WAS-02 Local current=B
→ 중복로그인
```

## 16. 이 구조는 JBoss API를 전혀 사용하지 않습니다.

### 16-1. 이 구조가 기존 `Map<String,HttpSession>`보다 나은 이유

| 항목                     |      기존 Session Map | 신규 Token 방식 |
| ---------------------- | ------------------: | ----------: |
| `HttpSession` JVM 간 공유 |                  불가 |       필요 없음 |
| JBoss API              |     클러스터 구현 시 필요 가능 |         불필요 |
| DB                     |                  없음 |          없음 |
| WAS-01→02 전달           |                 어려움 |        HTTP |
| Round-Robin 대응         |                 불안정 |          가능 |
| 중복종료 사유 표시             | 즉시 invalidate 시 어려움 |          가능 |
| HttpSession 객체 메모리 보관  |                  필요 |         불필요 |
| 동시 로그인                 |             Race 가능 |  version 비교 |
| Spring 5.3             |                  가능 |          가능 |
| JBoss EAP 7.2          |                  가능 |          가능 |

---

### 16-2. 중요한 한계

여기에는 기술적으로 반드시 명확히 해야 할 한계가 하나 있습니다.

```text
DB 없음
공유 Cache 없음
JBoss clustering API 없음
WAS간 통신도 없음
```

이라면 **서로 다른 JVM의 중복로그인을 100% 판별하는 것은 원리상 불가능합니다.**
따라서 이번 설계에서는:

```text
공유 DB 대신
WAS ↔ WAS 내부 HTTP
```

를 JVM 간 상태 전달 수단으로 사용합니다.
만약:

```text
WAS-01 ↔ WAS-02 내부 네트워크 단절
+
두 WAS 모두 L4에서 계속 사용자 요청을 처리
```

하는 완전한 Network Partition이 발생하면 일시적으로 두 WAS의 최신 token이 달라질 수 있습니다.
본 예제는:

```text
1차: 로그인 시 동기 HTTP 전파
2차: 실패 상태 ConcurrentHashMap 보관
3차: 5초 주기 재전파
```

까지 적용하여 이 가능성을 낮춥니다.
하지만 **DB/Redis/Infinispan/분산 Consensus 없이 완전한 원자적 분산 로그인을 보장하는 것은 불가능**합니다. 이것은 구현 문제가 아니라 분산 시스템의 구조적 제약입니다.
현재 요구조건에서는 위 HTTP peer 방식이 가장 현실적인 선택입니다.
-----------------------------------------

### 16-3. JBoss Session Cluster와의 관계

이번 중복로그인 제어 데이터:

```text
loginId → latest token
```

은 JBoss Infinispan을 직접 사용하지 않습니다.
다만 사용자 `HttpSession`이 WAS 간 이동해야 하는 환경에서는 기존 JBoss HTTP Session cluster는 그대로 필요합니다.

```text
HttpSession
 ├─ 기존 sessionVO
 ├─ __LOGIN_CONTROL_LOGIN_ID
 └─ __LOGIN_CONTROL_LOGIN_TOKEN
```

`<distributable/>`은 JBoss EAP에서 session replication을 활성화하기 위한 애플리케이션 측 전제입니다. ([Red Hat Customer Portal][2])
따라서:

```xml
<distributable/>
```

### 19-3. 특히 기존 코드에서 반드시 제거해야 할 부분

기존 소스에서 다음 패턴을 전체 검색하는 것을 권장합니다.

```java
invalidateByLoginId(
```

```java
oldSession.invalidate()
```

```java
loginUsers.get(loginId).invalidate()
```

```java
HttpSessionBindingListener.valueBound()
```

에서 기존 Session을 즉시 invalidate하는 부분은 모두 확인해야 합니다.
**신규 로그인으로 인한 기존 세션 종료는 `DuplicateLoginCheckFilter`에서만 실제 `invalidate()`되어야 합니다.**
정상 로그아웃이나 timeout에 의한 invalidate는 그대로 두어도 됩니다.

### 19-5. 최종 판단

| 요구사항                     | 결과                               |
| ------------------------ | -------------------------------- |
| DB 테이블 추가 없음             | **충족**                           |
| DB 컬럼 추가 없음              | **충족**                           |
| JBoss 자체 라이브러리 없음        | **충족**                           |
| Spring 5.3               | **충족**                           |
| JBoss EAP 7.2            | **적용 가능**                        |
| WAS 2대                   | **적용 가능**                        |
| Round-Robin              | **적용 가능**                        |
| 기존 세션 사용자 메시지            | **가능**                           |
| 기존 Session 즉시 invalidate | **하지 않음**                        |
| 보안상 기존 사용자의 업무 요청 차단     | **Filter에서 Controller 진입 전에 차단** |
| 정상 요청마다 DB 조회            | **없음**                           |
| 정상 요청마다 WAS간 HTTP        | **없음**                           |
| WAS간 HTTP 발생 시점          | **로그인 시 / Local 상태 유실 시만**       |
|                          | **없음**                           |

- |추가 JBoss JAR   이 구조에서 가장 중요한 것은 **“기존 Session을 살려둔다”는 것이 기존 사용자의 접근을 계속 허용한다는 뜻이 아니라는 점**입니다. 물리적인 `HttpSession` 객체만 다음 요청까지 남겨 두고, 모든 애플리케이션 요청보다 앞의 `DuplicateLoginCheckFilter`가 최신 token을 검사하므로 **새 로그인 발생 이후 기존 세션은 다음 요청부터 비즈니스 Controller에 진입하지 못합니다.** 
- 또한 이 방식은 현재 문제가 되었던 `request.getSession()`에 의한 새 세션 생성 문제도 `request.getSession(false)`를 사용하여 피할 수 있습니다. ([자카르타 EE][1])   
- 운영 적용 시에는 **기존 `LocalLoginPreventer`, `LoginSessionManager`, `SessionService`의 현재 소스와 위 예제를 병합하는 과정에서 `invalidate()`가 남아 있는 위치를 가장 먼저 점검**해야 합니다. 그 부분이 남아 있으면 중복로그인 메시지 표시가 다시 끊어집니다.                                                         |
