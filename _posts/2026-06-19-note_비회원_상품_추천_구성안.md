**BuyKorea**

**비회원 상품 추천 시스템 아키텍처 설계서**

확정안 (Final) — 자체 퍼스트파티 데이터 기반

# 1. 설계 개요

## 1-1. 목적

구글 검색 등을 통해 BuyKorea에 유입된 비회원 사용자에게, 외부 환경의 영향을 받지 않는 100% 정확한 자체 데이터를 기반으로 상품을 추천한다.

## 1-2. 설계 전제 (데이터 검증 결과 반영)

별첨 의사결정 보고서의 데이터 검증 결과, 기존 서치콘솔 기반 구글 자연검색어 1:1 매핑은 적중률 0.37%로 사실상 작동하지 않음이 확인되었다. 이에 본 설계는 불확실한 외부 데이터 매핑을 전면 배제하고, 검증 가능한 퍼스트파티 데이터만으로 구성한다.

|**배제 항목**|**사유**|
|---|---|
|서치콘솔 기반 구글 검색어 1:1 매핑|적중률 0.37%, 익명화로 표본 소멸|
|외부 서버(bdg-api.vercel.app) 의존|데이터 외부 유출, 통제 불가|

# 2. 추천 아키텍처 — 3트랙 구조

|**트랙**|**역할**|**데이터 출처**|**정확도**|
|---|---|---|---|
|Track 1|주력 추천|사이트 내부 검색어|100%|
|Track 2|콜드스타트 보완|랜딩페이지 컨텍스트|100%|
|Track 3|마케팅 분석|구글 서치콘솔(거시)|개인매핑 미사용|

## 2-1. Track 1 — 내부 검색어 기반 추천 (주력)

BuyKorea 사이트 내부 검색창에서 발생한 검색어를 사용자 식별자와 매핑하여 자체 DB에 저장하고, 이를 기반으로 상품을 추천한다.

•     비회원의 명확한 구매 의도가 담긴 100% 정확한 퍼스트파티 데이터

•     구글 정책 등 외부 환경의 영향을 전혀 받지 않음

•     검색 수행 즉시 동일 세션 내 추천 가능 (세션 식별)

•     bk_uid 쿠키 매핑으로 세션 종료 후 재방문 시에도 과거 검색어 기반 추천 가능

**처리 흐름**

① 사용자가 내부 검색창에 'korean cosmetics' 입력

② 검색 이벤트 발생 → 검색어 + 세션/사용자키 서버 전송

③ visitor_keyword 테이블에 저장

④ 검색어 기반 연관 상품 추천 API 호출

⑤ 검색 결과 및 추천 영역에 상품 노출

## 2-2. Track 2 — 랜딩페이지 컨텍스트 추천 (콜드스타트)

내부 검색 이력이 없는 최초 방문자 또는 검색을 수행하지 않은 사용자에게, 진입한 랜딩페이지의 문맥(카테고리·상품 상세)을 분석하여 연관 상품을 추천한다.

•     유입 검색어를 몰라도 '어떤 페이지를 보고 있는지'는 100% 추적 가능

•     진입 즉시 유효한 개인화 추천 제공 (콜드스타트 문제 해소)

**컨텍스트 추출 주체: 프론트엔드/GTM (백엔드 아님)**

BuyKorea는 CDN(Akamai) 엣지 캐싱이 적용되어, 최초 HTML 진입 요청이 백엔드까지 도달하지 않고 엣지 서버에서 응답될 수 있다. 이 경우 백엔드는 진입 URL을 알 수 없으므로, URL 파싱 및 컨텍스트 추출은 반드시 GTM/프론트엔드에서 수행한다.

**처리 흐름 (GTM 기반 컨텍스트 추출)**

① 사용자가 /category/cosmetics 또는 /product/123 진입

② GTM이 window.location.pathname 파싱 → 카테고리/상품 ID 추출

③ /api/recommend 호출 시 추출한 컨텍스트를 파라미터로 명시 전달

④ 서버: 전달받은 컨텍스트의 연관/인기 상품 반환

⑤ 추천 영역에 상품 노출

## 2-3. Track 3 — 서치콘솔 거시 마케팅 분석 (개인매핑 미사용)

구글 서치콘솔 데이터는 개별 사용자 매핑이 아닌, '어떤 키워드가 어떤 랜딩페이지로 트래픽을 유도하는가'를 파악하는 전체 트렌드 및 SEO 분석 용도로만 제한 사용한다.

•     랜딩페이지별 유입 키워드 그룹 분석

•     SEO 최적화 및 콘텐츠 전략 수립 근거

•     개별 bk_uid 매핑에는 일절 사용하지 않음

# 3. 단계별 추천 결정 로직

세션과 쿠키 식별자를 함께 활용하여 우선순위에 따라 단계적으로 추천을 적용한다.

|**우선순위**|**조건**|**적용 추천**|**식별 기준**|
|---|---|---|---|
|1순위|현재 세션 내 내부 검색 이력 있음 (방금/당일)|Track 1 (현재 검색어 기반 — 최고 의도)|세션|
|2순위|bk_uid 쿠키 보유 + 과거 검색 이력 있음|Track 1 (과거 검색어 기반 재방문 추천 — 잔존 의도)|쿠키|
|3순위|검색 이력 없음 + 카테고리/상품 페이지 진입|Track 2 (랜딩페이지 컨텍스트)|세션|
|4순위|위 모두 해당 없음 (메인 등)|기본 인기 상품 (Fallback)|-|

추천의 핵심 원칙은 '식별자의 영속성'이 아니라 '의도의 최신성'이다. 사용자가 방금 수행한 현재 세션의 검색은 가장 강력한 구매 의도를 나타내므로, 쿠키에 남은 과거 검색어보다 항상 우선한다. 예를 들어 어제 '화장품'을 검색한 사용자가 오늘 '전자부품'을 검색했다면, 현재 의도인 전자부품을 추천해야 한다. 쿠키 기반 과거 이력은 현재 세션 내 검색이 없을 때만 적용되는 잔존 의도(보조) 신호로 활용한다.

# 4. DB 테이블 설계

## 4-1. visitor (방문자 기본 정보)

| ----------- | ------------ | ---------------------- |
| id          | BIGINT (PK)  | 자동 증가 기본키              |

| referrer    | VARCHAR(255) | 유입 경로                  |

※ IP 주소는 추천 로직에 불필요하므로 저장하지 않거나 해시 처리 권장 (개인정보 최소수집 원칙).

## 4-4. 더미 데이터 통제 (스토리지·성능 최적화)

검색·클릭 등 의미 있는 행동 없이 메인 페이지만 보고 이탈하는 봇·단순 방문 트래픽이 많을 경우, 쓸모없는 레코드가 기하급수적으로 누적되어 스토리지 비용과 쿼리 성능을 악화시킨다. (실제 레거시 데이터 기준 전체 방문의 약 79%가 검색어 없는 행이었음)

|**통제 방식**|**내용**|
|---|---|
|행동 기반 저장|visitor_keyword는 검색·상품 클릭 등 유의미한 행동 발생 시에만 INSERT|
|TTL 배치 삭제|생성 30일 경과 + 매핑된 검색 이력 없는 visitor 더미 레코드 주기 삭제|
|파티셔닝|일자 기준 파티션으로 대량 삭제·조회 성능 확보|

# 6. 식별자 전략 — 세션 + 쿠키 동시 도입

## 6-1. 두 식별자의 역할 분담

1단계부터 세션 식별자와 퍼스트파티 쿠키(bk_uid)를 함께 도입한다. 두 식별자는 서로 다른 시간 범위의 사용자를 책임지며 상호 보완한다.

|**식별자**|**적용 범위**|**책임 추천**|
|---|---|---|
|session_id|당일 단일 세션 내|Track 1(당일 검색어) / Track 2(랜딩 컨텍스트)|
|bk_uid (쿠키)|세션 종료 후 ~ 30일 재방문|Track 1(과거 검색어 기반 재방문 추천)|

최초 방문 시 세션 식별자와 함께 bk_uid 쿠키를 발급하고, 검색 이벤트 발생 시 두 식별자 모두에 검색어를 매핑한다. 재방문 시 쿠키로 동일 사용자를 식별하여 과거 검색 의도를 이어서 추천한다.

**처리 흐름 (세션+쿠키 통합)**

① 최초 방문 → session_id 생성 + bk_uid 쿠키 발급(30일)

② 내부 검색 발생 → session_id + bk_uid에 검색어 동시 매핑

③ 당일 추천 → session_id 기준 즉시 추천

④ 세션 종료 후 재방문 → bk_uid 쿠키로 동일 사용자 식별

⑤ 과거 검색어 조회 → 검색 의도 기반 재방문 추천 제공

## 6-2. 퍼스트파티 쿠키 규격

Set-Cookie: bk_uid=xxxxxxxxxxxx;

           max-age=2592000;   (30일)

           path=/; SameSite=Lax; Secure

※ 구글이 차단한 것은 서드파티 쿠키이며, buykorea.org 자체 도메인의 퍼스트파티 쿠키는 정상 사용 가능. GTM/서버 통신 시 withCredentials=true 적용으로 쿠키를 정상 송수신한다.

## 6-3. 단계별 구축 로드맵

|**단계**|**범위**|
|---|---|
|1단계 (MVP)|세션 + 쿠키 동시 도입. Track 1·2·Fallback 전체 구현|
|2단계 (확장)|쿠키 기반 재방문 데이터 누적 → 추천 정확도 측정·개선|
|3단계 (고도화)|행동 데이터(클릭·체류) 결합한 추천 정교화|

# 7. 개인정보 처리 및 동의 기반 데이터 흐름 (필수)

BuyKorea는 글로벌 B2B 플랫폼으로 GDPR 등 해외 개인정보보호법의 영향을 받는다. 따라서 쿠키 동의(Opt-in) 상태에 따라 데이터 처리 흐름을 분기해야 한다.

## 7-1. 동의 상태별 처리 분기

|**구분**|**session_id**|**bk_uid** **쿠키**|**개인화 데이터 저장**|
|---|---|---|---|
|동의 전|발급 (기능 유지용)|발급 안 함|저장 안 함 (랜딩페이지 기반 즉시 추천만)|
|동의 후|유지|즉시 발급 (30일)|검색어 매핑·영속 저장 시작|

**핵심 원칙: 동의 전에는 개인화 목적의 데이터(검색어 매핑 등)를 저장하지 않는다.**

session_id가 동의 면제(Strictly Necessary)로 인정되려면 순수 기능 유지 목적이어야 한다. 검색어를 매핑해 추천에 활용하는 순간 분석·개인화 목적이 되므로, 동의 전 단계에서는 session_id에 검색어를 적재하지 않고, 추천은 서버에 저장하지 않는 랜딩페이지 기반 즉시 응답 방식으로만 제공한다.

## 7-2. 동의 후 이력 병합(Merge) 로직

사용자가 동의하기 전 당일 발생한 행동(검색·조회)을 살리기 위해, 동의 시점에 병합 처리를 수행한다.

① 동의 전: 추천은 즉시 응답(비저장)으로만 제공

② 사용자가 동의 배너에서 '동의' 선택

③ bk_uid 쿠키 즉시 발급 (30일)

④ 동의 이후 발생하는 검색/조회부터 bk_uid·session_id에 매핑·저장

⑤ (선택) 동의 직후 현재 세션의 검색 컨텍스트를 bk_uid에 병합 저장

※ 동의 전 클라이언트가 임시 보유한 당일 검색 컨텍스트를, 동의 직후 1회 서버에 전달하여 병합하는 방식은 법무 검토 후 적용한다.

## 7-3. 개인정보 최소수집 조치

|**조치 항목**|**내용**|
|---|---|
|처리방침 고지|쿠키·검색어(행태정보) 수집 사실 고지|
|동의 절차|비필수 쿠키 사전 동의(opt-in) 배너 적용|

# 9. 설계 개요

## 9-1. 목적

구글 검색 등을 통해 BuyKorea에 유입된 비회원 사용자에게, 외부 환경의 영향을 받지 않는 100% 정확한 자체 데이터를 기반으로 상품을 추천한다.

## 9-2. 설계 전제 (데이터 검증 결과 반영)

별첨 의사결정 보고서의 데이터 검증 결과, 기존 서치콘솔 기반 구글 자연검색어 1:1 매핑은 적중률 0.37%로 사실상 작동하지 않음이 확인되었다. 이에 본 설계는 불확실한 외부 데이터 매핑을 전면 배제하고, 검증 가능한 퍼스트파티 데이터만으로 구성한다.

|**배제 항목**|**사유**|
|---|---|
|서치콘솔 기반 구글 검색어 1:1 매핑|적중률 0.37%, 익명화로 표본 소멸|
|외부 서버(bdg-api.vercel.app) 의존|데이터 외부 유출, 통제 불가|

# 10. 추천 아키텍처 — 3트랙 구조

|**트랙**|**역할**|**데이터 출처**|**정확도**|
|---|---|---|---|
|Track 1|주력 추천|사이트 내부 검색어|100%|
|Track 2|콜드스타트 보완|랜딩페이지 컨텍스트|100%|
|Track 3|마케팅 분석|구글 서치콘솔(거시)|개인매핑 미사용|

## 10-1. Track 1 — 내부 검색어 기반 추천 (주력)

BuyKorea 사이트 내부 검색창에서 발생한 검색어를 사용자 식별자와 매핑하여 자체 DB에 저장하고, 이를 기반으로 상품을 추천한다.

•     비회원의 명확한 구매 의도가 담긴 100% 정확한 퍼스트파티 데이터
•     구글 정책 등 외부 환경의 영향을 전혀 받지 않음
•     검색 수행 즉시 동일 세션 내 추천 가능 (세션 식별)
•     bk_uid 쿠키 매핑으로 세션 종료 후 재방문 시에도 과거 검색어 기반 추천 가능

**처리 흐름**

① 사용자가 내부 검색창에 'korean cosmetics' 입력
② 검색 이벤트 발생 → 검색어 + 세션/사용자키 서버 전송
③ visitor_keyword 테이블에 저장
④ 검색어 기반 연관 상품 추천 API 호출
⑤ 검색 결과 및 추천 영역에 상품 노출

## 10-2. Track 2 — 랜딩페이지 컨텍스트 추천 (콜드스타트)

내부 검색 이력이 없는 최초 방문자 또는 검색을 수행하지 않은 사용자에게, 진입한 랜딩페이지의 문맥(카테고리·상품 상세)을 분석하여 연관 상품을 추천한다.

•     유입 검색어를 몰라도 '어떤 페이지를 보고 있는지'는 100% 추적 가능

•     진입 즉시 유효한 개인화 추천 제공 (콜드스타트 문제 해소)

**컨텍스트 추출 주체: 프론트엔드/GTM (백엔드 아님)**

BuyKorea는 CDN(Akamai) 엣지 캐싱이 적용되어, 최초 HTML 진입 요청이 백엔드까지 도달하지 않고 엣지 서버에서 응답될 수 있다. 이 경우 백엔드는 진입 URL을 알 수 없으므로, URL 파싱 및 컨텍스트 추출은 반드시 GTM/프론트엔드에서 수행한다.

**처리 흐름 (GTM 기반 컨텍스트 추출)**

① 사용자가 /category/cosmetics 또는 /product/123 진입

② GTM이 window.location.pathname 파싱 → 카테고리/상품 ID 추출

③ /api/recommend 호출 시 추출한 컨텍스트를 파라미터로 명시 전달

④ 서버: 전달받은 컨텍스트의 연관/인기 상품 반환

⑤ 추천 영역에 상품 노출

## 10-3. Track 3 — 서치콘솔 거시 마케팅 분석 (개인매핑 미사용)

구글 서치콘솔 데이터는 개별 사용자 매핑이 아닌, '어떤 키워드가 어떤 랜딩페이지로 트래픽을 유도하는가'를 파악하는 전체 트렌드 및 SEO 분석 용도로만 제한 사용한다.

•     랜딩페이지별 유입 키워드 그룹 분석

•     SEO 최적화 및 콘텐츠 전략 수립 근거

•     개별 bk_uid 매핑에는 일절 사용하지 않음

# 11. 단계별 추천 결정 로직

세션과 쿠키 식별자를 함께 활용하여 우선순위에 따라 단계적으로 추천을 적용한다.

|**우선순위**|**조건**|**적용 추천**|**식별 기준**|
|---|---|---|---|
|1순위|현재 세션 내 내부 검색 이력 있음 (방금/당일)|Track 1 (현재 검색어 기반 — 최고 의도)|세션|
|2순위|bk_uid 쿠키 보유 + 과거 검색 이력 있음|Track 1 (과거 검색어 기반 재방문 추천 — 잔존 의도)|쿠키|
|3순위|검색 이력 없음 + 카테고리/상품 페이지 진입|Track 2 (랜딩페이지 컨텍스트)|세션|
|4순위|위 모두 해당 없음 (메인 등)|기본 인기 상품 (Fallback)|-|

추천의 핵심 원칙은 '식별자의 영속성'이 아니라 '의도의 최신성'이다. 사용자가 방금 수행한 현재 세션의 검색은 가장 강력한 구매 의도를 나타내므로, 쿠키에 남은 과거 검색어보다 항상 우선한다. 예를 들어 어제 '화장품'을 검색한 사용자가 오늘 '전자부품'을 검색했다면, 현재 의도인 전자부품을 추천해야 한다. 쿠키 기반 과거 이력은 현재 세션 내 검색이 없을 때만 적용되는 잔존 의도(보조) 신호로 활용한다.

# 14. 식별자 전략 — 세션 + 쿠키 동시 도입

## 14-1. 두 식별자의 역할 분담

1단계부터 세션 식별자와 퍼스트파티 쿠키(bk_uid)를 함께 도입한다. 두 식별자는 서로 다른 시간 범위의 사용자를 책임지며 상호 보완한다.

|**식별자**|**적용 범위**|**책임 추천**|
|---|---|---|
|session_id|당일 단일 세션 내|Track 1(당일 검색어) / Track 2(랜딩 컨텍스트)|
|bk_uid (쿠키)|세션 종료 후 ~ 30일 재방문|Track 1(과거 검색어 기반 재방문 추천)|

최초 방문 시 세션 식별자와 함께 bk_uid 쿠키를 발급하고, 검색 이벤트 발생 시 두 식별자 모두에 검색어를 매핑한다. 재방문 시 쿠키로 동일 사용자를 식별하여 과거 검색 의도를 이어서 추천한다.

**처리 흐름 (세션+쿠키 통합)**

① 최초 방문 → session_id 생성 + bk_uid 쿠키 발급(30일)

② 내부 검색 발생 → session_id + bk_uid에 검색어 동시 매핑

③ 당일 추천 → session_id 기준 즉시 추천

④ 세션 종료 후 재방문 → bk_uid 쿠키로 동일 사용자 식별

⑤ 과거 검색어 조회 → 검색 의도 기반 재방문 추천 제공

## 14-2. 퍼스트파티 쿠키 규격

Set-Cookie: bk_uid=xxxxxxxxxxxx;

           max-age=2592000;   (30일)

           path=/; SameSite=Lax; Secure

※ 구글이 차단한 것은 서드파티 쿠키이며, buykorea.org 자체 도메인의 퍼스트파티 쿠키는 정상 사용 가능. GTM/서버 통신 시 withCredentials=true 적용으로 쿠키를 정상 송수신한다.

## 14-3. 단계별 구축 로드맵

|**단계**|**범위**|
|---|---|
|1단계 (MVP)|세션 + 쿠키 동시 도입. Track 1·2·Fallback 전체 구현|
|2단계 (확장)|쿠키 기반 재방문 데이터 누적 → 추천 정확도 측정·개선|
|3단계 (고도화)|행동 데이터(클릭·체류) 결합한 추천 정교화|

# 15. 개인정보 처리 및 동의 기반 데이터 흐름 (필수)

BuyKorea는 글로벌 B2B 플랫폼으로 GDPR 등 해외 개인정보보호법의 영향을 받는다. 따라서 쿠키 동의(Opt-in) 상태에 따라 데이터 처리 흐름을 분기해야 한다.

## 15-1. 동의 상태별 처리 분기

|**구분**|**session_id**|**bk_uid** **쿠키**|**개인화 데이터 저장**|
|---|---|---|---|
|동의 전|발급 (기능 유지용)|발급 안 함|저장 안 함 (랜딩페이지 기반 즉시 추천만)|
|동의 후|유지|즉시 발급 (30일)|검색어 매핑·영속 저장 시작|

**핵심 원칙: 동의 전에는 개인화 목적의 데이터(검색어 매핑 등)를 저장하지 않는다.**

session_id가 동의 면제(Strictly Necessary)로 인정되려면 순수 기능 유지 목적이어야 한다. 검색어를 매핑해 추천에 활용하는 순간 분석·개인화 목적이 되므로, 동의 전 단계에서는 session_id에 검색어를 적재하지 않고, 추천은 서버에 저장하지 않는 랜딩페이지 기반 즉시 응답 방식으로만 제공한다.

## 15-2. 동의 후 이력 병합(Merge) 로직

사용자가 동의하기 전 당일 발생한 행동(검색·조회)을 살리기 위해, 동의 시점에 병합 처리를 수행한다.

① 동의 전: 추천은 즉시 응답(비저장)으로만 제공

② 사용자가 동의 배너에서 '동의' 선택

③ bk_uid 쿠키 즉시 발급 (30일)

## 16-1. 법적 검토

### 16-1-1. 🚨 핵심 컴플라이언스 진단 (Executive Summary)

**"로그인을 안 했으니 개인정보가 아니다"라는 판단은 글로벌 프라이버시 법령상 가장 치명적인 오해입니다.** 비회원이라 할지라도 브라우저에 고유한 랜덤 값(예: `UUID=7a8b9c...`)을 주입하여 특정 기기나 브라우저를 다른 유저와 '단독으로 구별(Singling out)'하고, 그 위에 검색어 및 조회 상품 정보를 누적하여 프로파일링하는 순간, 한국·미국·EU 모두 이를 **'개인정보(또는 온라인 식별자 및 행태정보)'의 수집 행위로 간주**하여 엄격한 법적 의무를 부과합니다. 위배 여부는 "유저에게 고지 및 통제권(동의/거부권)을 적법하게 제공했는가"에 따라 결정됩니다.

### 16-1-2. 지역별 법적 규제 매커니즘 정밀 검토

#### 16-1-2-1. ① EU 기준: GDPR 및 ePrivacy 지침 (가장 엄격, 사전 동의 필수)

- **법적 지위**: **사전 동의(Opt-in) 없이 처리 시 100% 법률 위반**

- **상세 검토**:

    - **ePrivacy Directive (쿠키법)**: 유저의 단말기(PC/모바일 브라우저)에 정보를 저장하거나 접근할 때는 원칙적으로 **명시적인 사전 동의**를 받아야 합니다. 예외는 서비스 제공에 '엄격히 필수적인 쿠키(Strictly Necessary)'(예: 장바구니 담기 유지, 보안 세션)뿐입니다. 비회원의 검색어 분석이나 상품 추천용 쿠키는 필수 쿠키가 아니므로 동의 배너에서 유저가 승인하기 전에는 쿠키를 구워서는 안 됩니다.

    - **GDPR 제4조 및 전문(Recital) 30**: 쿠키 속 랜덤 고유 ID는 '온라인 식별자(Online Identifier)'에 해당하며, 이 식별자와 행태정보(검색·조회)가 결합되어 지속적인 행동 프로필을 구축할 수 있다면 이름·이메일을 모르더라도 개인데이터(Personal Data)로 분류됩니다.

#### 16-1-2-2. ② 미국 기준: CCPA / CPRA 및 주별 프라이버시법 (사후 거부 중심)

- **법적 지위**: **수집 자체는 가능하나, 활용 목적에 따라 엄격한 거부권(Opt-out) 및 고지 의무 발생**

- **상세 검토**:

    - **개인정보(PI)의 정의**: CCPA/CPRA는 특정 소비자 또는 가계(Household)와 합리적으로 연관 지을 수 있거나 연상할 수 있는 모든 정보를 개인정보로 봅니다. 랜덤 쿠키 ID + 상업적 기록(Commercial Information, 검색 및 조회 이력)은 명백한 개인정보입니다.

    - **자사 내부 최적화 용도(First-party Business Purpose)**: 수집한 비회원 데이터를 외부 애드테크 업체에 넘기지 않고 자사몰 서버 내에서만 "최근 본 상품", "연관 검색어" 노출 등 서비스 최적화용으로만 쓴다면 사전 동의 없이 수집 가능합니다. 단, 개인정보 처리방침(Privacy Policy)에 수집 항목과 목적을 투명하게 공개해야 합니다.

    - **제3자 타겟팅 광고 활용 시(Sale / Share)**: 만약 이 비회원 쿠키 ID와 검색 데이터를 구글, 메타, 크리테오 등 외부 솔루션(픽셀, SDK)과 연동하여 자사몰 밖에서 리타겟팅 광고를 하는 데 쓰인다면, 이는 데이터의 '판매(Sale)' 및 '공유(Share)'에 해당합니다. 이 경우 웹사이트 하단에 `"Do Not Sell or Share My Personal Information"` 링크를 의무적으로 상시 노출하여 유저가 거부할 수 있게 해야 하며, 거부 시 즉시 추적을 중단해야 위법이 아닙니다.

#### 16-1-2-3. ③ 한국 기준: 개인정보보호법(PIPA) 및 온라인 행태정보 보호 가이드라인

- **법적 지위**: **자사 내 한정 수집은 고지 후 거부권 제공으로 가능하나, 사후 회원 매핑 및 제3자 제공 시 위법 리스크 급증**

- **상세 검토**:

    - **온라인 행태정보(Behavioral Information)**: 로그인 전이라도 쿠키 ID와 결합된 검색·조회 이력은 유저의 기호, 성향을 분석할 수 있는 '행태정보'입니다.

    - **자사몰 내 서비스 제공**: 자사몰 시스템 개선이나 세션 유지를 위해 비회원 쿠키를 활용하는 경우, 개인정보보호법 제30조에 따라 **'개인정보 처리방침' 내에 [개인정보를 자동으로 수집하는 장치의 설치·운영 및 그 거부에 관한 사항(쿠키 거부 방법 등)]을 명확히 공개**하고, 유저가 브라우저 설정을 통해 통제할 수 있도록 안내하면 법 위반이 아닙니다.

    - **⚠️ 치명적 위반 주의점 (사후 결합 리스크)**: 비회원 상태에서 쿠키에 쌓아둔 'A 상품 검색', 'B 상품 조회' 이력을, 이 유저가 사흘 뒤 '회원 가입' 혹은 '로그인'을 하는 순간 회원 계정(식별 정보)과 강제로 결합(Mapping)하는 인프라를 동의 없이 가동한다면, 이는 개인정보 무단 수집 및 프로파일링으로 간주되어 법률 위반(시정명령 및 과징금 대상)이 됩니다. 결합하려면 회원가입/로그인 시점에 별도의 사전 동의(Opt-in)를 구해야 합니다.

### 16-1-3. 도입 및 이용 시 잠재적 위험성 (Risk Warning)

- **글로벌 최고 수천억 원대 행정처분 및 과징금**: 유럽 유저를 대상으로 사전 동의 없이 쿠키를 발급하여 검색 정보를 수집하다 적발될 경우 GDPR 위반으로 글로벌 연간 매출액의 최대 4%에 달하는 천문학적 과징금 폭탄을 맞을 수 있습니다.

- **빅테크 마케팅 플랫폼 인프라 폐쇄**: 쿠키를 통해 수집된 비회원 검색어 정보에 유저가 실수로 입력한 개인식별정보(이메일, 전화번호 등 PII)가 평문으로 섞여 구글(GA4)이나 메타 서버로 전송될 경우, 구글의 프라이버시 자동 스캔 시스템에 적발되어 자사 비즈니스의 광고 및 데이터 분석 계정이 사전 경고 없이 즉시 영구 정지(Suspended)되는 리스크가 존재합니다.
