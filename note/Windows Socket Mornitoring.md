커넥션 풀(Connection Pool)의 상태를 정확히 파악하려면, 소켓들이 실제로 재사용되고 있는지(`ESTABLISHED` 상태 유지), 아니면 계속 끊어지고 새로 생성되는지(`TIME_WAIT` 폭증)를 모니터링하는 것이 매우 중요합니다.

윈도우 11 환경에서 로컬 소켓의 생성부터 소멸까지의 라이프사이클을 직관적이고 정확하게 모니터링할 수 있는 4가지 방법을 추천해 드립니다.

### 1. TCPView 사용 (가장 추천하는 실시간 GUI 도구)

마이크로소프트 Sysinternals에서 제공하는 무료 공식 툴로, 커넥션 풀 동작을 시각적으로 모니터링할 때 가장 압도적으로 편리합니다.

- **다운로드:** 검색창에 `Sysinternals TCPView`를 검색하여 마이크로소프트 공식 홈페이지에서 다운로드(무설치 파일)합니다.
    
- **장점:** * 새로운 소켓이 생성되면 **초록색**, 연결이 끊어지면 **빨간색**, 상태가 변경되면 **노란색**으로 실시간 하이라이트 처리가 됩니다.
    
    - 특정 프로세스(예: Java, Node, Python 등)만 필터링해서 볼 수 있어, 해당 애플리케이션의 커넥션 풀이 설정한 갯수만큼 `ESTABLISHED`를 잘 유지하는지 한눈에 파악할 수 있습니다.
        

### 2. PowerShell을 활용한 상태 통계 확인 (CLI 강력 추천)

수십~수백 개의 소켓이 맺어지는 커넥션 풀 특성상, 개별 소켓을 보는 것보다 **'현재 어떤 상태의 소켓이 몇 개 있는지'** 통계로 보는 것이 유리합니다. `netstat`보다 훨씬 빠르고 유연합니다.

1. **PowerShell**을 실행합니다.
    
2. 상대방(DB나 API 서버) 포트 기준으로 소켓 상태를 그룹화하여 갯수를 확인하려면 아래 명령어를 입력합니다.
    

PowerShell

```
Get-NetTCPConnection -RemotePort [목적지포트] | Group-Object State
```

_(예: DB 포트가 3306이라면 `Get-NetTCPConnection -RemotePort 3306 | Group-Object State`)_

**결과 해석:**

- **Established:** 현재 풀에서 살아서 연결을 유지 중인 소켓의 수입니다. (최대 풀 사이즈 설정값과 비슷한지 확인하세요.)
    
- **TimeWait:** 연결이 종료된 후 대기 중인 찌꺼기 소켓입니다. 이 수치가 계속 치솟는다면 커넥션 풀이 소켓을 재사용하지 못하고 계속 버리고 있다는 뜻입니다.
    

### 3. 리소스 모니터(Resource Monitor) 사용 (내장 GUI 툴)

별도의 프로그램 설치 없이 윈도우 기본 툴로 특정 프로세스의 네트워크 상태를 보고 싶을 때 유용합니다.

1. `Windows 키 + R`을 누르고 `resmon`을 입력하여 실행합니다.
    
2. 상단의 **[네트워크]** 탭으로 이동합니다.
    
3. **'네트워크 활동이 있는 프로세스'** 목록에서 테스트 중인 애플리케이션(예: `java.exe`)의 체크박스를 선택합니다.
    
4. 하단의 'TCP 연결'을 확장하면, 해당 프로세스가 맺고 있는 로컬 주소, 원격 주소, 포트, 패킷 손실률 등을 실시간으로 확인할 수 있습니다.
    

### 4. 전통적인 `netstat` 활용

빠르게 명령 프롬프트(cmd)에서 특정 포트의 상태만 스냅샷처럼 찍어서 보고 싶을 때 사용합니다.

1. 명령 프롬프트를 엽니다.
    
2. 아래 명령어를 통해 특정 포트와 통신 중인 소켓들을 필터링합니다.
    

DOS

```
netstat -ano | findstr [포트번호]
```

_(옵션 설명: `-a` 모든 연결 표시, `-n` IP/포트를 숫자로 표시, `-o` PID 표시)_

3. 주기적으로(예: 2초마다) 상태를 갱신하며 보고 싶다면 끝에 숫자를 붙여줍니다. (종료는 `Ctrl + C`)

DOS

```
netstat -ano 2 | findstr [포트번호]
```

**💡 현재 어떤 종류의 애플리케이션(예: Spring Boot의 HikariCP, Node.js의 HTTP Agent 등)의 커넥션 풀을 튜닝 또는 확인하고 계신가요?** 사용 중인 프레임워크를 알려주시면, OS 레벨의 모니터링 외에 애플리케이션 내부에서 직접 로그(log)나 메트릭을 뽑아내어 정확한 풀 동작을 교차 검증하는 방법을 안내해 드리겠습니다.
