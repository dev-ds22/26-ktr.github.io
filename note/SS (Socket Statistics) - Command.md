리눅스 및 유닉스 환경에서 네트워크 상태를 점검할 때 필수적으로 자리를 잡은 **`ss -tan`** 커맨드의 명확한 의미와 용도, 그리고 실무에서 함께 자주 쓰이는 네트워크 추천 커맨드 5개를 정리해 드립니다.

## 1. `ss -tan` 커맨드의 의미

`ss`는 **Socket Statistics**의 약자로, 과거에 사용하던 `netstat`을 대체하기 위해 만들어진 최신 명령어입니다. 커널의 네트워크 정보를 직접 가져오기 때문에 속도가 매우 빠르고 서버 부하가 적습니다.

뒤에 붙은 `-tan` 옵션은 각각 다음과 같은 의미를 가집니다.

- **`-t` (TCP):** UDP나 유닉스 도메인 소켓 등을 제외하고, 현재 가장 많이 쓰이는 **TCP 소켓 프로토콜 정보만 필터링**하여 보여줍니다.
    
- **`-a` (All):** 현재 연결이 완료된(ESTABLISHED) 소켓뿐만 아니라, 연결을 기다리는 중인(LISTEN) 소켓, 연결이 끊어지는 중인(CLOSE_WAIT, TIME_WAIT) 소켓 등 **모든 상태(State)의 소켓을 전부 출력**합니다.
    
- **`-n` (Numeric):** 포트 번호나 IP 주소를 문자(예: `http`, `ssh`, `localhost`)로 변환하지 않고 **숫자(예: `80`, `22`, `127.0.0.1`) 그대로 표시**합니다. 문자로 변환하는 과정에서 발생하는 DNS 조회 지연을 막아주므로 운영 환경에서는 필수 옵션입니다.
    

## 2. 언제, 어느 용도로 주로 사용되는가?

네트워크 상태 분석, 특히 **서버 애플리케이션(WAS, 웹 서버, DB 등)의 장애 조치 및 모니터링** 시나리오에서 주로 사용됩니다.

- **포트 오픈 및 바인딩 확인 (LISTEN):** 내가 방금 구동한 JBoss, Tomcat, Spring Boot가 설정한 포트(예: 8080)로 정상적으로 서버를 열고 대기 중인지 확인할 때 사용합니다.
    
- **커넥션 누수(Socket Leak) 진단 (CLOSE_WAIT):** 애플리케이션 소스 코드에서 소켓을 제때 닫지 않으면 `CLOSE_WAIT` 상태의 커넥션이 무한히 증가합니다. `ss -tan | grep CLOSE_WAIT` 명령어로 누수 여부를 실시간으로 감시할 수 있습니다.
    
- **서버 트래픽 및 접속자 수 파악 (ESTABLISHED):** 현재 우리 서버에 실시간으로 접속해서 데이터를 주고받는 클라이언트가 몇 명인지 파악하고 싶을 때 사용합니다.
    
- **포트 고갈 위험 감지 (TIME_WAIT):** 단시간에 수많은 연결이 맺어졌다 끊어지면 소켓이 `TIME_WAIT` 상태로 유지됩니다. 이 개수가 너무 많으면 서버의 가용한 포트가 고갈되어 더 이상 접속을 받지 못하므로, 이를 사전에 인지하기 위해 카운트합니다.
    

## 3. 비슷하게 많이 쓰이는 유용한 네트워크 커맨드 5개 추천

실무에서 `ss -tan`과 함께 양대 산맥을 이루거나, 특정 상황에서 더 유용하게 쓰이는 명령어 5개입니다.

### ① `ss -tlpn` (포트를 점유한 '범인 프로세스' 찾기)

현재 서버에서 **열려 있는(Listen) TCP 포트만** 깔끔하게 보여주며, 결정적으로 "어떤 프로그램(PID와 프로세스명)"이 그 포트를 차지하고 있는지 명시해 줍니다. (단, 프로세스 정보를 보려면 `root` 또는 `sudo` 권한이 필요합니다.)

- **명령어:** `sudo ss -tlpn`
    
- **용도:** "톰캣을 띄우려는데 8080 포트가 이미 사용 중이래요!" 할 때 어떤 프로세스가 범인인지 찾을 때 제격입니다.
    

### ② `ss -s` (서버 네트워크 상태 3초 컷 요약 리포트)

수천, 수만 개의 소켓 리스트를 한 줄씩 다 보여주는 대신, 현재 서버 전체의 소켓 상태를 종류별로 요약해서 숫자로 보여줍니다.

- **명령어:** `ss -s`
    
- **용도:** 서버 전체의 대략적인 건강 상태를 볼 때 씁니다. (예: "지금 TIME_WAIT 소켓이 총 1만 개나 되네?" 같은 빠른 진단 가능)
    

### ③ `lsof -i :[포트번호]` (특정 포트 핀포인트 저격)

`ss`와 결과물은 비슷하지만, 여러 포트를 다 보지 않고 **내가 관심 있는 특정 포트 하나만 딱 지정해서** 어떤 프로세스가 쓰고 있는지 직관적으로 확인할 때 가장 가독성이 좋은 명령어입니다.

- **명령어:** `lsof -i :8080`
    
- **용도:** 8080 포트를 쓰고 있는 프로세스의 실행 명령어, PID, 사용자, 소켓 상태를 단 한 줄로 깔끔하게 파악할 때 씁니다.
    

### ④ `nc -zv [목적지IP] [포트번호]` (원격지 포트 오픈 테스트)

`nc`(Netcat)는 네트워크 연결을 테스트하는 최고봉 도구입니다. 대상을 지정해 해당 포트가 열려있는지(방화벽이 뚫려있는지) 즉시 체크합니다.

- **명령어:** `nc -zv 192.168.0.10 3306`
    
- **용도:** 내 서버에서 원격지에 있는 DB 서버(3306 포트)나 외부 API 서버로 연결이 정상적으로 가능한지(방화벽 차단 여부 등) 검증할 때 필수적입니다.
    

### ⑤ `tcpdump -i [인터페이스] port [포트번호]` (실시간 패킷 캡처)

네트워크 카드(NIC)로 드나드는 실제 패킷 데이터 흐름을 실시간으로 캡처하여 화면에 뿌려주거나 파일로 저장합니다.

- **명령어:** `sudo tcpdump -i eth0 port 8080 -Xvv`
    
- **용도:** "소켓 연결은 맺어졌는데 왜 데이터 응답이 안 올까?"를 분석할 때, 실제로 네트워크 레벨에서 요청과 응답(Request/Response) 패킷이 정상적으로 오가고 있는지 날것(Raw)의 데이터를 확인할 때 쓰는 가장 강력한 트러블슈팅 툴입니다.
